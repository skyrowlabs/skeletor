## Setup

```bash
{{SETUP_COMMANDS}}
./{{CLI}} check pre-push
```

`check pre-push` is everything CI blocks on, in the order that fails fastest. On
a freshly scaffolded tree it passes — if it does not, that is a bug in the
scaffold, not something to work around.

## The CLI

Every gate, generator, and maintenance job in this repo is a subcommand of
`./{{CLI}}`, and CI calls the same subcommands you do. There is no command list
in this README on purpose: command groups are discovered by scanning `cli/`, so
a list here would be a second copy that goes stale the first time someone adds
one.

```bash
./{{CLI}} --help              # every group
./{{CLI}} check --help        # the gates
```

See [`docs/CLI.md`](docs/CLI.md) for the architecture behind that discovery, and
why it is a package rather than a script.

## Conventions

- Conventional commits (`feat`/`fix`/`docs`/`chore`/`refactor`/`ci`/`test`), one
  subject line. The `commit-msg` hook enforces it.
- Generated files carry a `<!-- GENERATED by ... -->` banner and are never
  hand-edited — change the generator and re-run it.
- Work in progress lives in `docs/TODO/` until it is finished, then gets filed
  into `docs/implementations/`. Nothing is tracked in someone's head.
