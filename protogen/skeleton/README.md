```bash
make up          # http://localhost:@@PORT@@

make logs

```

## What is generated and what is not

`app/models.py`, `app/routes.py`, `app/seed.py`, `app/templates/*.html` and
`tests/test_smoke.py` carry a GENERATED banner -- they are rewritten whole by
`proto add`. Everything else (the Dockerfile, compose file, `app/main.py`,
`app/db.py`, the stylesheet, `tests/conftest.py`) is the fixed skeleton, and
is identical in every protogen app.

Editing a generated file is fine -- it is your repo now -- but the next
`proto add` will overwrite it.

## Data

There are no migrations and no volume. The database is a tmpfs that is
recreated with the container, and `app/seed.py` refills it on startup. To
reset, `make down && make up`.
